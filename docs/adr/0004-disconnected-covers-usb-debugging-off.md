# "未连接"状态同时涵盖"未插入"与"未开启 USB 调试"

`adb devices` 只能看到已经在运行 adbd 协议的设备。手机插着数据线但完全没打开"开发者选项 → USB 调试"时，adb 层根本看不到这台设备——这与压根没插手机在协议层面是同一种表现，无法区分。

因此 `DeviceMonitor` 不单独区分"未开启调试"这一种状态：`disconnected` 状态的引导文案里直接包含"如果已插入手机但没有反应，请检查是否开启 USB 调试"的提示，覆盖这两种物理场景。真正能被 adb 区分出来的是"设备已出现在 `adb devices` 列表但未授权"，这种情况对应独立的 `unauthorized` 状态。

**后果**：用户看到的"未连接"文案已经把两种可能原因都讲清楚，但 UI 上不会把它们拆成两个状态。如果未来要精确区分，需要引入操作系统级别的 USB 设备枚举（如 macOS 的 `system_profiler SPUSBDataType`）按厂商 ID 识别"有 Android 设备物理连接但未运行 adbd"，这明显更复杂，目前判断不值得为此增加复杂度。
